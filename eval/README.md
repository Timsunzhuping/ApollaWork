
## 失败样本 → 评测/微调闭环（T-420）

生产里的失败任务与用户 👎 会沉淀为样本：管理后台「导出失败样本」得到 JSONL
（每行：意图、模式、模型路由、状态、评分/备注、用量、压缩轨迹 `steps`）。用法：

1. 人工标注：给每条样本补 `expected`（期望行为/产物）与 `category`（工具调用格式 / 规划 / 文件产出 / 超时 / 幻觉）；
2. 回归：把高价值样本改写成 `eval/golden` 场景（校验点机器可判），进入发布闸门；
3. 微调：`category` 分布指导提示词迭代或蒸馏集构建（T-303/T-416 的输入）。

样本不含工作区文件内容与密钥；`steps` 里的工具入参/结果已是 runtime 截断后的摘要。
